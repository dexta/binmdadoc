This project started with the goal of bringing both text-based markup languages side by side. It stems from the need to quickly test, store, and potentially share texts with others.

== The long journey of handling these with Go

After hours of searching for a way to get AsciiDoc working with Golang, it became clear that there is no way around Asciidoctor and Ruby—the only full-featured implementation available. The idea was to build a Ruby web service that provides an HTML response for any text input.

While this sounds easy to develop, it is hard to master without prior experience in non-Rails Ruby web services. Initial research showed that for years, developers have been satisfied with the JRuby version of Asciidoctor.

Now, this project continues in a subfolder under the main project, restarting with a Node.js version of the initial Golang attempt. Unfortunately, the best implementation for Markdown also resides in the server-side JavaScript ecosystem.

The current plan is as follows:
* *Golang* will handle the frontend and save both the source and the final HTML file.
* *Node.js* will act purely as a backend service to receive the source and return the HTML documents.
* *Ruby* might replace `asciidoctor.js` at some point in the future.

=== And the winner is: mdadoc

The project is named after the mount point on a Docker Swarm node.

After setting up a new DevOps environment, there is a clear need to test the infrastructure for future use, understand the running application, and monitor the resources required for the job.

=== Gitlab ci/cd build stuFF

build tags a nice rabbithole to deploy with

[source,yml]
----
build_and_push:
  stage: deploy
  image: docker:stable
  services:
    - docker:dind
  script:
    - echo "$CI_REGISTRY_PASSWORD" | docker login $CI_REGISTRY -u $CI_REGISTRY_USER --password-stdin
    # Nutzt die Git-Tag-Variable (z.B. v1.0.0) als Container-Tag
    - docker build -t $CI_REGISTRY_IMAGE:$CI_COMMIT_TAG .
    - docker push $CI_REGISTRY_IMAGE:$CI_COMMIT_TAG
  only:
    - tags  # Dieser Job läuft NUR, wenn du ein Git-Tag erstellst

----
